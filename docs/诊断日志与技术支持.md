# Auto Voucher 诊断日志与技术支持

## 1. 两类日志的边界

Auto Voucher 同时保留两套用途不同的记录：

| 类型 | 回答的问题 | 是否可按保留策略清理 |
| --- | --- | --- |
| 财务审计日志 | 谁在什么时间导入、修改、确认、导出、推送或恢复了什么 | 否，只允许追加 |
| 诊断日志 | 程序运行到哪一步、为什么失败、建议如何处理 | 是，默认保留 30 天 |

诊断日志不能替代财务审计日志，也不会修改业务状态。

## 2. 采集范围

诊断日志采用结构化事件，覆盖：

- 应用启动、停止和版本；
- 启动器环境检测、下载、签名/哈希校验、安装、健康检查、更新和回退；
- 本地 HTTP 接口的失败响应与重要写操作；
- 数据导入、OCR 和同步后台任务的排队、开始、完成、失败与耗时；
- 飞书、金蝶等连接器的认证、权限、限流、网络、主数据和校验错误；
- 浏览器脚本错误、未处理异步异常和业务状态持久化失败；
- 备份和脱敏诊断包导出；
- 日志保留与磁盘相关控制。

每条记录包含：

- 发生时间、级别、模块和稳定事件代码；
- 面向财务人员的问题描述和建议操作；
- 请求、后台任务或诊断包支持编号；
- 操作、业务对象和耗时；
- 脱敏后的结构化上下文；
- 异常类型、消息和必要的调用栈；
- 应用版本与来源端。

## 3. 财务人员操作

打开“凭证工作台 → 诊断日志”：

1. 优先点击“一键复制问题信息”，直接取得面向用户的脱敏摘要；
2. 如需定位明细，再按级别、模块、时间和关键词筛选；
3. 点击单条“复制”，发送问题、建议操作和支持编号；
4. 如单条记录不足，选择 1、7、30 或 90 天并导出脱敏诊断包；
5. 发送前检查 ZIP 中的 `README.txt`、`environment.json`、`runtime-summary.json`、`state-summary.json` 和 `logs.jsonl`。

剪贴板被浏览器拒绝时，系统显示可全选文本并提供 `.txt` 下载。工作台无法打开时，Windows 启动窗口仍会复制启动阶段的问题信息。

接口失败时，页面错误提示会附带 `REQ-...` 支持编号，可直接在诊断日志中搜索。

## 4. 诊断包内容

诊断包包含：

- `manifest.json`：文件大小和 SHA-256 完整性清单；
- `README.txt`：支持编号、时间范围和安全说明；
- `environment.json`：操作系统、应用/Python 版本、数据库大小、可用磁盘和保留策略；
- `state-summary.json`：业务对象数量和连接器能力/状态摘要；
- `logs.jsonl`：指定时间范围内的结构化脱敏日志。
- `runtime-summary.json`：环境检测、核心/启动器版本、更新状态和最近启动器错误的脱敏摘要。

诊断包不包含：

- 原始票据、附件和归档文件；
- 凭证头、分录、摘要或客商业务数据；
- SQLite 数据库或完整备份；
- API 密钥、访问令牌、密码、Cookie 或授权头；
- 完整银行账号、身份证号、个人邮箱或用户主目录路径；
- 连接器用户名、地址、账套账号等非必要配置。

## 5. 保留策略

- 默认保留 30 天，最多 50,000 条；
- 可配置范围为 7–365 天、5,000–500,000 条；
- 每累计写入 100 条会自动执行过期和超量清理；
- 保留策略只作用于诊断日志，不会删除审计日志、凭证、业务事项或原始资料。

## 6. 开发定位约定

- `REQ-...`：一次本地 HTTP 请求；
- `JOB-...`：一次后台任务；
- `AV-YYYYMMDD-...`：一次诊断包；
- `DLOG-...`：一条诊断记录。
- `ENV-...`：一次环境检测；
- `ROLLBACK-...`、`UPDATE_...`：启动器更新或回退故障。

技术支持应先按支持编号聚合，再根据 `eventCode`、前后时间和 `durationMs` 判断故障阶段。不得要求财务人员直接发送完整业务备份来替代诊断包。
