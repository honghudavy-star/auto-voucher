### 正文

最近一直在做一个开源项目，叫 Auto Voucher。

起因很简单：很多财务资料本来已经在审批单、Excel、流水和票据里了，但到了记账环节，还是要重新整理字段、选科目、补部门和项目，再录进 ERP。

我不想把它做成“扔进去一张票，系统替你把账做完”。

真正落地时，麻烦的地方远不止识别一张票：

目标 ERP 是哪个版本？

有 API，还是只能导入模板？

科目、供应商、部门和项目怎么对应？

审批有没有真的通过？

测试账套能不能保存并回查到凭证草稿？

网络超时以后，到底该重试还是先查重？

所以现在的工作台分成几步：

1. 先选企业、目标 ERP、数据来源和业务场景；
2. 判断走 API，还是走 ERP 导入模板；
3. 配置科目、供应商、客户、部门、项目等基础资料；
4. 配置凭证规则，并由财务人员确认；
5. 在测试账套通过检查后，再开放生产导出或推送；
6. 日常再到凭证工作台里导入、复核、推送和查询。

数据默认放在自己的电脑里。连接器只保存凭证草稿，不会替用户自动审核、过账或结账。

现在已经支持常见文件导入，也做了飞书审批、金蝶云星空、用友 U8、浪潮海岳的适配框架。但这里必须说清楚：ERP 的产品版本、部署方式和接口授权差异很大，自动化测试通过，不等于每个客户账套都已经打通。真实使用前还是要拿客户的接口资料和测试账套验收。

我把完整代码放在 GitHub 上了。这个项目还在继续完善，如果你正在使用金蝶、用友、浪潮，或者手上正好有一套固定的 ERP 导入模板，欢迎把产品和版本告诉我。

GitHub：`honghudavy-star/auto-voucher`

## 二、实机录像视频脚本

### 视频定位

- 建议时长：12–16 分钟
- 画面：Windows 11 真机，1920 × 1080，30 fps
- 形式：全程录真实操作，旁白后配或现场讲解均可
- 目标：让观众看明白它现在能做什么、怎么操作、哪里仍需要客户资料
- 不录：静态 PPT、概念动画、虚构 API 成功、自动审核或自动过账

### 录制前准备

1. 使用虚构企业和测试账套，名称可写成“华南新程商贸有限公司”“录制测试账套”。
2. 准备一份虚构的费用报销 XLSX，至少包含日期、金额、摘要、员工、部门和项目。
3. 再准备一份缺少部门的异常文件，用来录真实阻断。
4. 如果没有厂商测试账套，就不填写真实连接密钥，只展示“待客户资料验证”和预检阻断。
5. 清空浏览器通知、下载记录和个人书签；不要录到用户名、家庭 IP、Token、密钥或本机完整路径。
6. 浏览器缩放设为 100%，录制前走完一遍操作，确保画面不会横向溢出。
7. 将系统声音关闭，只保留鼠标点击声或后期旁白。

## 三、逐段画面与旁白

### 00:00–00:35 直接展示问题

**实机操作**

先打开费用报销表，停留 3 秒。切到浏览器中的 Auto Voucher，再打开一张凭证草稿或空的凭证工作台。

**旁白**

> 这是一份普通的费用报销表。日期、金额、员工和部门其实都已经有了，但要变成 ERP 里的凭证，还要重新整理字段、选科目、补辅助核算，再检查借贷是否平衡。我做 Auto Voucher，就是想把中间这段重复工作整理成一条看得见、能复核的流程。

**屏幕字幕**

`业务资料 → 凭证草稿`

### 00:35–01:20 它是什么

**实机操作**

回到工作台首页。鼠标依次经过“接入方案、系统与数据、凭证规则、测试上线、凭证工作台、系统工具”，不要快速乱点。

**旁白**

> 这是一个开源、本地运行的凭证自动化工作台。数据默认保存在这台电脑上，页面通过本机浏览器打开。它负责导入资料、生成凭证草稿、组织人工复核，再按实际条件交给 ERP。
>
> 我先把边界说清楚：它不会替财务人员自动审核、过账或者结账。自动化处理重复劳动，最终确认仍然交给人。

### 01:20–02:45 第一次打开：接入方案

**实机操作**

1. 点击“接入方案”。
2. 展示企业名称、法人主体、账套、账簿、本位币、凭证字和操作者。
3. 选择一个目标 ERP 品牌、产品、版本和部署方式。
4. 勾选“文件”来源和“费用报销”场景。
5. 点击“生成接入方案”。
6. 停留在右侧生成结果，慢慢滚动。

**旁白**

> 第一次使用，不需要先研究接口文档。先把企业、账套、目标 ERP、数据来源和准备自动化的业务场景选清楚。
>
> 系统会根据本地的能力目录判断，这个组合能不能走 API，还是更适合使用 ERP 的导入模板。如果当前版本没有经过验证，页面会直接写“待客户资料验证”，不会猜一个接口出来。

**录制重点**

必须拍到真实点击后的结果状态。如果页面提示缺少字段，就保留这个提示，补齐后再次生成，不要剪成一次成功。

### 02:45–04:15 系统与数据：连接以前先对资料

**实机操作**

1. 点击“系统与数据”。
2. 展示目标系统状态、测试账套和模板档案区域。
3. 展示科目、供应商、客户、部门、项目等基础资料入口。
4. 打开环境检测卡片。

**旁白**

> 接下来要确认两件事：系统能不能连，数据能不能对上。
>
> 如果走 API，要测试认证、权限、期间和回查。如果走文件，就要保存 ERP 的空白模板、成功样例、必填列和字段格式。
>
> 凭证中的科目、供应商、部门和项目也不能凭空填写。客户提供基础资料以后，可以在这里同步或导入。目标系统、版本或者账套一旦变化，之前的验证会失效，需要重新检查。

### 04:15–05:05 环境检测和复制问题信息

**实机操作**

1. 执行一次环境检测。
2. 展开一个检查结果。
3. 点击“复制问题信息”。
4. 打开记事本，粘贴复制出的脱敏摘要。

**旁白**

> 这个工具面向的不只是技术人员，所以环境问题不能只扔一串报错。这里会检查 Windows、磁盘、本地端口、数据库、网络和浏览器。
>
> 遇到问题可以直接复制摘要。这里不会自动上传票据、凭证、数据库或连接密钥，用户可以先看过内容，再决定要不要发给维护人员。

**录制重点**

记事本中的内容必须是真实复制结果。录完后逐行检查，确认没有用户名、完整路径、账号或业务数据。

### 05:05–06:35 凭证规则：没有万能默认科目

**实机操作**

1. 点击“凭证规则”。
2. 新建或打开一条费用报销规则。
3. 展示字段映射、借贷分录和辅助核算。
4. 故意保留一个缺少部门映射的状态。
5. 点击验证，拍下阻断提示。
6. 补齐后再次验证，但是否启用由录制条件决定。

**旁白**

> 到这一步才开始定义凭证怎么生成。规则里包括字段映射、借贷分录、科目和辅助核算。
>
> 系统不预填所谓的万能借贷科目，规则也不会创建以后立刻启用。字段、科目和辅助核算完整，再由财务人员确认，才能真正使用。现在我故意少配一个部门，页面会直接阻断，不会静默塞进一个示例值。

### 06:35–07:50 测试上线：连接成功不等于能生产

**实机操作**

1. 点击“测试上线”。
2. 展示连接、权限、期间、主数据、模板导入、草稿保存、回查和财务确认。
3. 点击尚未开放的生产操作，录下真实阻断原因。

**旁白**

> 能连上接口，只能说明第一步通过了。正式使用以前，还要确认会计期间、基础资料、测试草稿保存、回查和重复请求处理。
>
> 只要有一项硬门槛没有通过，生产导出和推送就不会开放。现在没有真实 ERP 测试账套，所以这里停在阻断状态。我不把它做成假的成功画面。

### 07:50–10:20 凭证工作台：导入一份真实测试文件

**实机操作**

1. 展开“凭证工作台”。
2. 点击“导入资料”。
3. 选择准备好的费用报销 XLSX。
4. 展示预览、字段映射和导入结果。
5. 进入“业务事项”，打开刚才生成的事项。
6. 进入“生成与复核”，查看凭证草稿；如果门槛未满足，就展示待配置或阻断结果。
7. 展开后再次点击“凭证工作台”，拍到菜单可以正常收起。

**旁白**

> 配置完成以后，日常工作主要在凭证工作台里。现在导入一份测试报销表。
>
> 文件上传本身不代表审批通过，所以审批状态不会被自动改成通过。系统先保存来源和去重依据，再根据已经确认的规则生成业务事项。
>
> 如果规则和基础资料都完整，就可以生成借贷平衡的凭证草稿；如果不完整，它会创建待配置事项或异常，不会为了让页面好看而硬生成一张凭证。

**录制重点**

不要口述“已经生成”但画面显示空状态。旁白必须跟随当次实机结果。

### 10:20–11:10 异常样例

**实机操作**

导入缺少部门的第二份文件，进入异常详情，展示缺失字段、影响位置和处理建议。

**旁白**

> 再看一份有问题的数据。这一行缺少部门辅助核算，所以系统把它停下来，并告诉我缺什么、影响哪一项、应该在哪里补。
>
> 对财务系统来说，明确停下来通常比悄悄填错更重要。修复以后重新验证，前后的操作也会留下记录。

### 11:10–12:05 系统工具和日志

**实机操作**

1. 点击一级入口“系统工具”。
2. 展示连接器、OCR、通用设置、诊断日志、备份与恢复。
3. 再次点击“系统工具”，拍到正常收起。
4. 展开“凭证工作台”，证明两个菜单互斥。

**旁白**

> 连接器、OCR、通用设置、诊断和备份这些低频功能，现在单独放在系统工具里，不再和日常凭证步骤混在一起。
>
> 凭证工作台和系统工具都可以再次点击收起，展开一个时，另一个会自动收起。

### 12:05–13:10 启动和更新

**实机操作**

Windows Docker 版本录制以下流程：

1. 执行 README 中的 Docker Desktop 一键启动命令。
2. 录制 Docker Desktop 检测、镜像拉取、本地服务启动和浏览器打开。
3. 打开版本与更新状态。

如果当前构建尚未正式发布，就不录“发现新版本”或“更新完成”。

**旁白**

> 普通用户不需要安装 Git、Python 或 Node.js。执行 Docker Desktop 一键启动命令以后，脚本会检查 Docker、拉取预构建镜像、启动本地服务，再打开浏览器。
>
> 程序和业务数据分开保存。再次执行同一条命令即可更新镜像；健康检查失败时会保留数据卷并回退到可用版本。

### 13:10–14:10 目前做到哪里

**实机操作**

回到“接入方案”，展示支持的来源和目标 ERP 选项。对尚未验证的选项停留在“待客户资料验证”。

**旁白**

> 目前可以处理 CSV、XLSX、XML、XBRL、OFD、PDF、图片和银行流水，也做了飞书审批，以及金蝶云星空、用友 U8、浪潮海岳的适配框架。
>
> 但 ERP 接口会受到产品版本、部署方式、模块授权和账套权限影响。程序里的自动化合同测试，不等于每个客户环境都已经打通。真实上线仍然需要接口资料和测试账套。
