# 国内 ERP 自动导入凭证模板调研

更新日期：2026-07-27

## 结论

国内 ERP 不存在“一家厂商一份永久固定的凭证导入模板”。模板通常同时受产品线、具体版本、账套科目、辅助核算、币别、凭证字和已安装模块影响。可靠的接入方式应是：

1. 先确定产品、版本和部署方式；
2. 从目标测试账套内下载或导出该版本的空白模板；
3. 再从同一账套导出一张包含借贷两行、辅助核算、外币/数量字段的脱敏样例；
4. 用测试账套做“导入—校验—回查”，通过后才登记为已验证模板。

本次没有把论坛里的旧版宏文件、收费附件或来源不明的 XLS/XLSM 当作官方模板。这些文件可能绑定旧数据库结构、含宏，或与当前账套字段不一致。

| --- | --- | --- | --- | --- |

| 金蝶 EAS Cloud 8.6 | TXT，分隔符可配置 | 在“外部凭证引入控制参数”中选择字段并设置列号，再按该顺序生成 TXT | 官方字段配置和导入流程公开；实际模板由账套配置决定 | 实现“字段顺序 + 分隔符 + 编码”的 TXT 导出器 |
| 金蝶精斗云 / 云会计 | Excel | 登录产品后，在凭证相关页面下载/按导入模板格式导出 | 可确认存在模板流程；未找到无需登录的官方静态空表 | 从客户测试账套下载，不使用第三方网盘样表 |

## 需要向测试用户采集的文件

每个“产品 + 版本 + 部署方式”单独建立一套档案，至少收集：

- 系统内下载的原始空白模板，不改名、不另存；
- 一张从系统导出的脱敏凭证样例，至少包含两条平衡分录；
- 科目编码、凭证字、币别、部门、客户、供应商、职员、项目和成本中心的脱敏编码样例；
- 模板下载入口、产品完整版本号、部署方式、账套标识和下载日期；
- 一次测试导入的原始结果或错误日志；
- 导入后凭证的外部编号、状态和只读回查结果。

建议的最小测试凭证覆盖：

| 场景 | 需要覆盖的字段 |
| --- | --- |
| 普通人民币凭证 | 日期、凭证字/类别、摘要、科目编码、借方、贷方 |
| 辅助核算 | 部门、客户或供应商、职员、项目/成本中心 |
| 外币 | 币别、汇率、原币金额、本位币金额 |
| 数量核算 | 数量、单价、计量单位 |
| 结算信息 | 结算方式、结算号、银行账号（若产品支持） |

## 推荐实施顺序

1. **好会计**：官方入口清楚、Excel 模板路径明确，先拿测试账套实表。
2. **金蝶 EAS Cloud 8.6**：官方规则最清楚，先实现可配置 TXT 导出。
3. **金蝶云·星空**：优先验证现有 WebAPI 草稿保存；文件模板作为客户账套特例。
4. **用友 U8**：按版本逐一采集，不复用论坛旧宏表。
5. **用友 NC / 浪潮 GS Cloud**：优先接口和项目实施资料，不把通用 Excel 当作默认路线。
6. **管家婆、浪潮云会计、航天 A6、速达**：有真实测试用户和版本后再建立模板。

只有“模板原件 + 目标版本 + 测试账套成功导入 + 回查”全部具备，才把状态从“待客户资料验证”改为“测试导入通过”。
