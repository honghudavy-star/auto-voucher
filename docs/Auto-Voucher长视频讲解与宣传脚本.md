# Auto Voucher 长视频讲解与宣传脚本

## 视频定位

- **建议时长**：16–20 分钟
- **画面规格**：16:9，1920 × 1080，30 fps
- **目标观众**：中小企业财务人员、代账人员、财务负责人、企业数字化负责人
- **核心承诺**：把“业务资料到凭证草稿”的重复工作变成一条可配置、可复核、可追踪的本地流程
- **表达边界**：不宣称替代会计判断；不宣称客户 ERP 已经直连；不演示自动审核、过账或结账

## 录制前准备

1. 使用虚构企业、虚构客户和专用测试账套，不录入真实客户信息。
2. 准备一份结构清晰的费用报销 XLSX，以及一份带有缺失部门的异常样例。
3. 提前配置一条演示规则，但在视频中从“未启用”开始展示人工确认。
4. ERP 部分优先使用客户提供的测试账套；没有真实测试账套时只展示连接方案和预检结果，不伪造成功推送。
5. 将浏览器缩放设为 100%，关闭无关标签、通知、密码管理器弹窗和个人书签栏。
6. 开启鼠标高亮；录屏中所有账号、地址、密钥、Token 和完整本机路径必须遮挡。
7. 录制前完整走一遍流程，并确认诊断摘要不包含业务数据。

## 完整脚本与分镜

### 00:00–00:40 开场：财务人员真正卡在哪里

**画面**

- 快切三个画面：审批单、Excel、ERP 凭证录入界面。
- 最后停在 Auto Voucher 五入口首页。

**旁白**

> 很多企业并不缺业务数据，真正耗时间的是把审批单、Excel、银行流水和票据，重新整理成 ERP 能接受的凭证。字段要对，科目要对，辅助核算不能漏，最后还要有人复核。Auto Voucher 想解决的，就是这段重复、容易出错、但又不能失去控制的工作。

**字幕**

`资料分散｜重复录入｜规则难统一｜出错难追踪`

### 00:40–01:45 产品是什么，又不是什么

**画面**

- 展示本地架构简图。
- 依次高亮“本地核心”“系统浏览器”“SQLite”“ERP 草稿”。

**旁白**

> Auto Voucher 是一个开源、本地优先的财务凭证自动化工作台。数据默认保存在用户自己的电脑里，工作台在系统浏览器中打开。它负责导入资料、识别业务事项、按规则生成借贷平衡的凭证草稿、组织人工复核，再把草稿交给 ERP。
>
> 这里有一条非常重要的边界：系统不会自动提交、审核、过账或结账。自动化负责减少机械工作，最终会计责任仍然由财务人员掌握。

**字幕**

`只生成和保存草稿｜不自动审核｜不自动过账`

### 01:45–03:00 为什么不是“上传文件就完成”

**画面**

- 展示五个一级入口。
- 用动画依次连线：接入方案 → 系统与数据 → 凭证规则 → 测试上线 → 凭证工作台。

**旁白**

> 真正能上线的凭证自动化，不是上传一个表格就宣布完成。首先要知道资料从哪里来、凭证要进入哪个系统；然后要确认 API 能不能用，还是只能走导入模板；还要同步科目、供应商、客户、部门和项目，配置会计规则，最后在测试账套验证。Auto Voucher 把这十几项准备工作整理成五个入口，让不熟悉接口的用户也知道下一步该做什么。

### 03:00–05:15 第一步：接入方案

**画面操作**

1. 打开“接入方案”。
2. 选择目标 ERP 品牌、产品、版本和部署方式。
3. 添加数据来源和费用报销场景。
4. 生成数据流程方案。
5. 展示“API / 模板 / 待客户资料验证”状态。

**旁白**

> 第一步不要求用户先懂 API。我们只需要按实际情况选择企业、账套、目标 ERP、数据来源和业务场景。系统会根据本地版本化能力目录，确定应该采用 API 直连，还是文件模板导入。
>
> 如果某个产品版本没有经过验证，界面会明确标记“待客户资料验证”，而不是猜测接口名称或假装已经支持。最终方案会列出数据流、人工节点、阻断项和回查方式。

**字幕**

`先判断连接方式，再设计流程`

### 05:15–07:20 第二步：系统与数据

**画面操作**

1. 打开“系统与数据”。
2. 展示 API 连接、模板档案和测试账套区域。
3. 展示科目、供应商、客户、部门、项目等基础资料。
4. 打开环境检测卡片。

**旁白**

> 第二步解决的是“系统能不能连、数据能不能对上”。API 路径需要验证认证、权限、会计期间和回查能力；文件路径需要保存空白模板、成功样例、表头指纹和必填列。
>
> 同时，凭证里的科目和辅助核算不能凭空产生。系统需要同步或导入科目、供应商、客户、部门、项目、员工、成本中心、币种和税码。每个系统都保留最后验证时间和环境，配置变化后，旧的验证结果会自动失效。

**环境检测旁白**

> 对小白用户来说，环境问题必须能被看懂。Auto Voucher 会检查 Windows 版本、磁盘空间、本地端口、SQLite、网络、浏览器和可选识别组件。遇到问题，可以一键复制脱敏摘要，不需要用户打开终端找日志。

### 07:20–09:20 第三步：凭证规则

**画面操作**

1. 打开“凭证规则”。
2. 展示字段映射、基础资料映射和会计分录。
3. 显示一条“未启用”规则。
4. 故意缺少一个部门映射，展示阻断信息。
5. 补齐后人工确认并启用。

**旁白**

> 第三步才是配置凭证怎么生成。规则包括字段映射、基础资料映射、审批依据、借贷分录、辅助核算和异常阻断。
>
> 规则默认不启用，也没有所谓“万能默认科目”。只有字段完整、科目存在、辅助核算齐全并由财务人员确认，规则才能启用。如果客户还没有给出规则，系统创建的是待配置事项，而不是替用户做会计判断。

**字幕**

`没有万能科目｜规则必须人工确认`

### 09:20–11:15 第四步：测试上线

**画面操作**

1. 打开“测试上线”。
2. 展示连接、权限、期间、主数据、草稿保存、回查、幂等和财务确认门槛。
3. 展示一个未通过项目。
4. 点击生产启用，演示被阻断。
5. 说明通过后仍需再次确认公司、账套、环境和批量上限。

**旁白**

> 第四步是系统最重要的安全门槛。测试写入只能进入测试账套，而且连接器只允许保存草稿。连接成功不等于可以上线，还要验证期间、主数据、模板导入、草稿保存、回查、幂等和财务确认。
>
> 只要存在一个硬阻断项，生产导出和推送就不会开放。全部通过以后，还要再次确认目标公司、账套、生产环境和单次批量上限。

### 11:15–14:10 第五步：凭证工作台完整演示

**画面操作**

1. 导入准备好的费用报销 XLSX。
2. 展示原始资料哈希和事项列表。
3. 展示审批状态为“未知”，不自动变成通过。
4. 运行识别与规则匹配。
5. 打开凭证草稿，检查摘要、借贷金额、科目和辅助核算。
6. 人工复核并确认。
7. 展示推送预检和回查入口。

**旁白**

> 完成配置后，日常工作主要在凭证工作台里进行。现在导入一份费用报销表。系统会保留原始资料的哈希，用于去重和追踪。
>
> 文件上传不代表审批已经通过，所以审批状态仍然是未知。规则匹配也不会显示一个固定置信度，而是根据真实证据给出结果。生成草稿后，财务人员可以检查摘要、借贷金额、科目和每一项辅助核算。
>
> 确认之前，系统再次校验借贷平衡和上线门槛。确认之后才能进入推送预检。保存草稿后还必须拿到外部编号或通过幂等引用回查；网络超时但状态不明时，系统会转人工核对，不会盲目重发。

### 14:10–15:20 异常不是失败，而是控制

**画面操作**

1. 导入缺少部门的异常样例。
2. 展示阻断原因、建议和定位字段。
3. 展示修复后重新验证。

**旁白**

> 凭证自动化最有价值的地方，不只是处理正常数据，更是把异常提前暴露。这个样例缺少部门辅助核算，系统不会静默填一个示例值，而是明确告诉用户缺少什么、影响哪条分录、应该去哪里补齐。修复之后再重新验证，整个过程都会留在审计记录中。

### 15:20–16:30 启动、更新和失败回退

**画面**

- 展示 Windows 启动器。
- 展示更新状态、重启阻断原因和版本信息。
- 用示意动画说明“新版本目录 → 健康检查 → 成功切换 / 失败回退”。

**旁白**

> 用户不需要安装 Python 或 Node.js。首次双击轻量安装器后，启动器会检测环境、下载核心程序、启动本地服务并打开浏览器。
>
> 日常更新会在后台下载，但如果正在导入、推送、写入状态或备份，系统不会强制重启。切换版本前先备份 SQLite，新版本健康检查失败时自动回到旧版本。

**字幕**

`业务数据与程序版本分离｜更新前备份｜失败自动回退`

### 16:30–17:25 数据和密钥放在哪里

**画面**

- 展示“本地数据 / 原始资料 / 程序 / 日志”四个独立区域的示意图。
- 展示一键复制诊断摘要，敏感字段打码。

**旁白**

> 程序、业务数据、原始资料、缓存和日志分开保存，程序更新不会覆盖业务目录。连接器密钥只进入操作系统密钥库，不写入 SQLite、日志或备份。诊断信息默认排除票据原文、凭证分录、数据库、Token 和客户业务数据，也不会自动上传。

### 17:25–18:35 当前支持范围和诚实边界

**画面**

- 列出飞书审批、文件来源、金蝶、用友、浪潮。
- 在 ERP 名称旁显示“适配器框架 / 客户环境验收”。

**旁白**

> 当前版本支持飞书审批，以及 CSV、XLSX、XML、XBRL、OFD、PDF、图片和银行流水文件。目标系统提供金蝶云星空、用友 U8 V12+ 和浪潮海岳 GS Cloud 的版本化适配器框架。
>
> 但厂商接口通常受到产品版本、部署方式、模块授权和客户权限影响。程序通过模拟合同测试，不代表每个客户账套已经打通。真实上线仍然需要客户提供接口资料和测试账套，完成保存草稿与回查验收。

### 18:35–19:20 结尾与行动号召

**画面**

- 回到五入口首页。
- 显示 GitHub 仓库、下载地址和 Issue 入口。

**旁白**

> 如果你的团队也在重复整理审批单、Excel、流水和票据，可以从一个高频业务场景开始：先确定目标 ERP 和测试账套，再配置一条规则，跑通一张凭证草稿。Auto Voucher 已经开源，你可以下载体验、查看代码，或者提交你正在使用的 ERP 产品和版本。真正可靠的自动化，不是跳过财务控制，而是让每一步更清楚、更可验证、更容易追踪。

**字幕**

`开源｜本地优先｜从一个场景开始`

## 后期剪辑建议

- 前 30 秒每 3–5 秒切换一次画面，之后保持每 8–15 秒有一次视觉变化。
- 所有点击动作先停顿半秒再操作，关键按钮使用局部放大，不使用夸张音效。
- 术语第一次出现时加一句解释，例如“幂等：同一笔业务不会因为重试而重复生成”。
- 对等待下载、导入和检查的过程做合理加速，并保留“已加速”字幕。
- 遇到真实接口尚未验证的页面，保留“待客户资料验证”状态，不用后期遮盖或替换成成功。
- 背景音乐控制在旁白音量的 10%–15%，错误提示和安全边界段落降低或暂停音乐。

## 发布文案

### 视频简介

Auto Voucher 是一个开源、本地优先的财务凭证自动化工作台。本视频完整演示如何从目标 ERP 和数据来源开始，配置基础资料与凭证规则，通过测试上线门槛，再把 Excel、审批单等资料生成可复核、可回查的凭证草稿。

系统默认只保存草稿，不自动提交、审核、过账或结账。ERP 真实连接能力取决于客户的产品版本、接口授权和测试账套。

- 项目地址：https://github.com/honghudavy-star/auto-voucher

- 问题反馈：https://github.com/honghudavy-star/auto-voucher/issues

Windows 安装器当前未使用 Authenticode，系统可能显示“未知发布者”。请只从项目仓库或官方更新地址下载，并核对 Release 中的 SHA-256。
