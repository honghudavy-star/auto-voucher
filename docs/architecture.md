# Auto Voucher 本地架构决策

> 状态：已采用
> 更新日期：2026-07-25

## 当前形态

Auto Voucher 是本机单用户程序，不是官网，也不是多租户 SaaS。浏览器只负责呈现工作台；正式数据源是本机 SQLite 与原件归档目录。

```text
Docker Desktop 预构建镜像（Compose、健康检查、数据卷、失败回退）
  → 本机浏览器
  → 127.0.0.1:8765 本地 HTTP 服务
      → SQLite（业务状态、凭证、审计）
      → archive/（SHA-256 内容寻址原件）
      → CSV / XLSX / XML 解析器
      → 同版本内置 PDF Worker（文本提取与首页渲染）
      → 同版本内置 RapidOCR Worker（扫描 PDF / 图片，仅生成候选）
      → 操作系统密钥库（连接器密钥，不进入备份）
      → 飞书审批 v4（已审批实例增量同步）
      → 金蝶云·星空 WebAPI v6（主数据/期间/凭证草稿）
      → 用友 U8 V12+ / 浪潮海岳 GS Cloud（版本化配置、凭证草稿与回查）
```

## 已采用的决策

1. 本地服务使用 Python 标准库 `ThreadingHTTPServer`，强制只监听回环地址。理由是单机版无需部署 Web 框架，运行依赖更少。
2. 金额始终使用整数分，写入 SQLite 前再次校验凭证借贷平衡。
3. 原始文件以完整 SHA-256 为身份，按哈希前缀分目录归档；相同内容只保存一次。
4. CSV、分隔型 TXT、XLS、XLSX、XML 在服务端解析；文本型 PDF 提取可搜索文本；扫描 PDF/图片由本地 RapidOCR 生成候选字段，关键字段经人工确认后才创建业务事项。
5. 前端操作仍由确定性规则执行，状态以事务方式写回 SQLite。后续多用户版需把命令和并发控制进一步下沉到服务端。
6. 备份使用 ZIP，包含状态快照与全部原始文件；恢复时防止路径穿越并重新建立去重索引。
7. 外部系统只允许通过连接器 API/官方导入模板对接，不直接写财务系统数据库。
8. 未知表格先预览表头和样例，由用户确认必填字段；模板使用表头指纹匹配，避免仅按文件名误用。
9. 待审核、待处理或已确认但未推送的凭证允许编辑；保存前重新执行借贷校验，已确认凭证编辑后撤销确认并记录前后差异、原因和操作者。
10. 规则使用结构化匹配条件和借贷科目动作，按优先级选择；凭证永久引用生成时的规则 ID 和版本。
11. 超过交互阈值的导入任务在后台线程执行并回报进度；大列表渲染有 100 行上限，使用搜索缩小范围。
12. 生产代码不提供演示推送；幂等、Outbox、保存后回查和不明状态禁止重发由真实适配器合同测试覆盖。
13. 飞书同步只接收明确 `APPROVED` 的实例；字段映射不足时生成阻断异常，不猜测业务字段。
14. 金蝶连接器固定使用 Save 保存草稿并关闭自动提交审核；推送前检查确认状态、审批、目标环境、能力、会计期间、目标科目和辅助核算。
15. 连接器配置变更会使环境锁和上次连接测试失效；生产环境要求 HTTPS，并在配置和推送时分别显式确认。
16. 网络超时先按幂等引用回查；未查到结果时进入“状态待确认”，Outbox 转人工核对并禁止自动重发。
17. Windows 端只通过 Docker Desktop 运行预构建镜像；镜像更新由重新拉取
    `latest` 并通过健康检查后替换容器完成，业务数据始终保存在命名数据卷。

## 暂不采用

- Electron/Tauri：Docker 版使用系统浏览器访问本地服务，不携带浏览器内核。
- PostgreSQL：单机版本 SQLite 已足够；多人并发版再迁移。
- 自动跳过人工审核：与产品边界冲突，暂不提供。
- 将未校验 OCR 文本直接生成正式凭证：风险不可接受。
- 直接把 API 密钥写入 SQLite：连接器密钥只允许写入操作系统密钥库。
