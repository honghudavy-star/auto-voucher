# Feature: 辅助核算主数据自动校验

## Requirements

- 当用户在凭证场景的分录中选择辅助核算维度时，系统必须保存该维度对应的目标主数据分类、取值来源和必填规则。
- 当系统根据场景生成凭证时，系统必须保留所有实际使用的辅助核算值，并在目标账套主数据中解析其唯一有效编码。
- 当辅助核算为空、未配置目标字段、目标主数据不存在、已停用或同名不唯一时，系统必须给出精确到分录的错误并阻止确认或推送。
- 当凭证推送到 ERP 前，系统必须在服务端重新校验目标科目和全部已填写辅助核算，不得只依赖客户端检查。
- 当校验失败或目标 ERP 不可用时，系统不得自动创建客户、供应商或其他主数据，也不得自动提交、审核或过账凭证。

## Architecture

### Frontend

- 场景分录使用 `dimensionBindings` 描述可配置辅助核算；旧的 `dimensions` 和 `requiredDimensions` 在读取时迁移。
- 凭证生成阶段将场景取值解析为 `dimensions` 原始值，并保留 `dimensionRefs` 中的类型、分类和来源信息。
- 凭证详情展示主数据校验结果；客户端继续检查必填值，但不作为最终安全边界。

### Backend

- `ConnectorService.preflight()` 调用统一辅助核算校验器。
- 校验器按 `connectorId + category + code/name + active` 匹配已同步主数据，编码优先，名称只允许唯一精确匹配。
- 匹配成功后使用目标编码生成供连接器保存的凭证副本；原始输入和匹配证据保留在校验报告中。
- 金蝶保存函数拒绝未解析的结构化辅助核算引用，只发送解析后的 `FNumber`。

### Security

- 服务端只接受内置辅助核算目录中的类别，不接受来自场景的任意 FormId 或字段名。
- 所有错误均失败关闭；目标 ERP 查询失败不伪装为“主数据不存在”。
- 不返回或记录连接器密钥；审计信息仅包含凭证、分录、类别和主数据编码。
- 沿用现有环境锁、最小权限、幂等键、草稿保存和保存后回查边界。

## Acceptance Criteria

- 供应商名称唯一匹配时转换成供应商编码并允许推送。
- 相同名称存在多个有效编码时阻止推送并报告“匹配不唯一”。
- 客户值不能因为同名供应商存在而通过校验。
- 非必填但已填写的辅助核算不存在时同样阻止推送。
- 已停用、其他连接器或其他分类下的主数据不能通过校验。
- 缺少目标字段映射时在保存前失败。
- 旧场景仍可读取并迁移为新的绑定结构。
- 全部通过后只调用保存草稿，不调用提交、审核或过账。
